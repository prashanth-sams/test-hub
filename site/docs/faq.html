FAQ

Short answers with links to the long ones. If something here is wrong, the code is the authority and an issue is welcome.

Does it work with my framework?

If it can write JUnit/xUnit XML — pytest, JUnit, Surefire, Gradle, Jest, Playwright, PHPUnit, gotestsum, Mocha, and most others — yes, today, with no plugin. If it cannot, write Test Hub's canonical JSON from a twenty-line script, or write an adapter.

Test Hub deliberately does not claim to accept "any JSON" or "any XML". A format that guesses produces silently wrong numbers, which is worse than a refusal. Unrecognised input returns a 415 listing what this server does accept.

Do I need Python on the build agent?

No. The REST API is the product and curl is a first-class publisher:

shell
curl -X POST "$HUB/api/v1/imports" \
  -H "Authorization: Bearer $TEST_HUB_TOKEN" \
  -F "file=@results.xml" -F "project=payments-api" -F "type=component"

The Python SDK is a convenience for people who already have Python, never a requirement.

What happens if I publish the same report twice?

Without a --run-id, you get two runs — which is correct, because two genuine executions of the same suite are two runs. With the same --run-id, the second import applies zero events and changes no count:

shell
$ test-hub ingest report.json -p storefront-web --run-id 3f2a91c4-… --json | jq '{events_applied, events_ignored}'
{ "events_applied": 0, "events_ignored": 12 }

Every write is idempotent twice over: UNIQUE(source, event_id) at the event level, and X-Idempotency-Key at the batch level. Retry freely.

How do I make four parallel shards into one run?

Generate a UUID once before the shards start and pass it to every one as --run-id. Order does not matter, and re-running a single shard is safe. Worked examples for both GitHub Actions and Jenkins.

Why does my pass rate show as "—"?

Because nothing executed. The pass-rate denominator excludes skipped and cancelled tests, so a run where everything was skipped has no pass rate at all. Showing 0% would read as total failure, which is the opposite of the truth. See Metrics.

Why does a retried test count once?

Because it is one test. A retry is recorded as a second attempt, never as a second test and never as an overwrite of the first. The test contributes once to the counts through its last attempt, so a test that failed and then passed is green — and because the earlier attempt is still there, it is also flaky. Counting it twice would inflate the total and make the pass rate wrong.

A test shows 100% flake rate but its history is all green. Why?

Because it passes only when it is retried. Flakiness is measured two ways: within a run (the attempts disagreed) and across runs (the outcome disagreed with its own history). A test that fails then passes on every single run is green every time and flaky every time — which is exactly the thing worth telling you about.

Why does it refuse to start on 0.0.0.0?

Because you did not configure authentication, and a Test Hub reachable from a network with no authentication lets anyone who can reach the port read and write every test result. Either create a token, or say --insecure-no-auth and accept a warning on every start. There is no silent path to an open instance.

Where does the data live, and how big does it get?

Under TEST_HUB_DATA_DIR — a platform data directory by default, listed in Configuration. One SQLite file plus a content-addressed artifacts/ tree.

Size is driven almost entirely by captured output, not by test counts: a run of a few thousand tests with no logs is small, and one test with a 200 KiB stack trace is not. Text fields are capped by TEST_HUB_MAX_TEXT_FIELD_BYTES (256 KiB by default) and truncation is flagged rather than silent. Artifacts are deduplicated by SHA-256, so fifty shards uploading the same screenshot store one copy.

Can I use PostgreSQL?

Not in this release. Storage sits behind RunRepository, EventRepository and ArtifactStore precisely so that it can, and Deployment describes what would change. The shipped implementation is SQLite because pip install and run — with no services — is worth more for a first release than horizontal write throughput.

Why is there no Node, no bundler, no framework?

Three reasons, in order of how much they mattered: a Content-Security-Policy of default-src 'none' is only possible with no inline scripts and no remote origins; a Python package that needs npm to build is a packaging liability; and the whole application is about fifteen small files, which does not need a framework.

The dashboard fetches nothing from the internet either, so an air-gapped install renders exactly like a connected one. CI fails the build if any src or href in the page points off-origin.

Why only one server worker?

The live-update bus is in-process. Two workers would hold two buses, and half the connected dashboards would miss half the events. There is deliberately no --workers flag. Replacing the bus with Redis Streams or NATS is the fix, and the EventBus protocol is where it goes.

What is deliberately not in this release?

Test authoring or manual test management; test execution and orchestration; AI-generated failure analysis; SSO, SAML and SCIM; full multi-tenancy; Kubernetes manifests; licence enforcement; and notifications or issue-tracker integrations.

The extension points are in place for several of these — every row is scoped to a workspace from the first migration, and authentication sits behind an interface — but none of them were allowed to delay a working vertical slice.

How does it compare with what I already have?

If one framework in one repository is all you have, a per-framework HTML reporter is simpler and you should use one. Test Hub earns its place when results arrive from several languages, several teams and several pipelines, and nobody can answer "is the suite healthier than last week?" without opening six tabs.

Something is wrong. Where do I look?

SymptomLook at
Import rejectedThe error body lists every installed adapter. Adapters.
Numbers look wrongMetrics — the formulas are written out, with worked examples.
Dashboard not updatingThe connection pill in the header. The stream and the proxy_buffering trap in Deployment.
Server will not startExit code 78 is a configuration error and the message says what to change.
Anything elseGET /healthz reports the version, schema version, database reachability and workspace id, and contains no secrets — safe to paste into an issue.
